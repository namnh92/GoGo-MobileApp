# ADM-205 — Saved has no map and groups by province and commune

Refs #214. Consumes GoGo-BE#585 (ADM-022, OpenAPI 1.0.0-alpha.33; the vendored `openapi/gogo.v1.yaml` is byte-identical to that PR's head). Stacked on #239 (ADM-204), whose location source order it reuses.

## Behaviour

- **No map.** The list/map toggle and the map view are gone for places and plans alike. The filter chips (all, places, plans) stay.
- **Groups come from the server's `SavedItem.area`.** Province first, then commune, both from canonical codes and names. The client never derives an area from coordinates or text.
- **Plans follow the BE policy.** A plan whose stops share a commune sits in that commune. Stops across several communes of one province sit in that province's "Nhiều phường/xã" subgroup, which comes last within the province. Stops across provinces go to "Nhiều tỉnh/thành phố". A plan or place with any unmapped stop goes to "Chưa xác định khu vực". Nothing is dropped.
- **Current area first.** The source order is Home's (ADM-204). A fresh position is sent to `GET /administrative/locate` and the returned commune and province go first. Without one, the account area is used when its status is `current`. Without either, nothing is marked current. The current group carries a "Khu vực hiện tại" chip, so position is never signalled by order alone.
- **Deterministic Vietnamese order.** Provinces and communes sort by the Vietnamese alphabet (ă, â, đ, ê, ô, ơ, ư as letters), then tone, ignoring the unit word ("Thành phố", "Phường", "Xã"). Ties keep server order.
- **No pagination.** `GET /me/saved` returns the whole list in one response, so grouping sees every item and no page boundary can duplicate or reorder a group.
- **Save/unsave.** An optimistic save lands in the unknown group until the server answers with its area. A saved place whose details fail to load renders as unavailable and can still be removed.
- **Privacy.** The located position is a query key under `location`, which is not in the persisted query prefixes. It never reaches storage.

## Validation

See the pull request for command output. Covered by `saved-groups.test.ts` (Vietnamese alphabet and tones, unit word, province and commune order, several-commune last, current commune and whole-province current, no duplicates, missing labels as unknown, located position not persisted) and `saved-areas.spec.tsx` (no map or toggle, located order, account-area fallback, no location, plan warnings and filters, plan open and remove, unavailable place removal, error retry, signed-out prompt).

Not run: device acceptance (permission granted/denied, account switch, real saved data), DEV against a deployed #585.

## Rollback

Revert this PR; Saved returns to the list/map view. Deploy GoGo-BE#585 first. An older backend omits `area`, which the generated type requires, so this build must not ship ahead of the backend.
