# APP-058 — notifications and location in one settings screen

Refs #216. Stacked on NTF-APP-010 (#215, PR #235), whose account switch it reuses as a section.

Profile has one "Thông báo và vị trí" row instead of two. Both earlier routes, `/settings/notifications` and `/settings/location`, render the same combined screen, so older in-app navigation still lands correctly. The screen has two headed sections. Notifications shows the account switch and this device's notification permission. Location shows this device's foreground location permission with the correct action per state: allow when never asked, Open Settings when denied (iOS restricted reports as denied), manual area as fallback when unavailable. Returning from OS Settings re-reads both permissions; the location section previously re-read only on navigation focus, which does not fire on app foreground. A signed-out person keeps the location section and is offered sign-in for the account switch only. The default area stays in Account information, with a pointer there; it is never treated as GPS permission.

Validation: `api:check`, `tsc --noEmit`, `expo lint` pass; vitest 283 passed / 39 skipped (includes the profile-rows test); jest 30 suites / 170 tests passed. The jest process exited rc 0 without the watchdog, but jest reported one worker it force-exited after the run (Mobile #133 leak class).

Not run: Android/iOS devices, screen-reader pass on device, DEV deploy.
