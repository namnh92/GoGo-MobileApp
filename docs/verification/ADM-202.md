# ADM-202 — room area from the canonical picker

Refs #207. Consumes GoGo-BE#581 (ADM-020, OpenAPI 1.0.0-alpha.32; the vendored `openapi/gogo.v1.yaml` is byte-identical to that PR's head).

## Behaviour

The create wizard's location step offers two choices that exclude each other:

- **Current location**: asked on tap, stored as the origin, with a maximum distance.
- **An administrative area** from the shared province → commune picker (ADM-201), a commune or the whole province, stored with its dataset version and labels.

Choosing one clears the other. An area is a scope, not a position: its centre is never stored as the origin, and the distance options are shown only for a device position. Google area autocomplete and the curated service-area list are no longer used by the wizard.

The account area (ADM-203) is offered as a chip only while the draft has no location choice, applied by a tap (ADR-0022), and not offered when its dataset has been replaced or to a guest.

The request carries `constraint.administrativeArea` as `{ datasetVersion, provinceCode, communeCode }` only; labels stay local. Continuing with an area from a replaced dataset keeps the user on the step with the reselection notice, and a create refused with `ADMINISTRATIVE_VERSION_CHANGED` shows the same notice instead of a generic failure.

## Drafts

Saved drafts move to version 2 and keep the area's codes, dataset version and labels through back, save and resume. A version-1 draft whose area came from autocomplete or a service area (a key plus its centre) drops that pick and its centre and resumes at the location step; a version-1 device position is kept.

## Rollback

Revert this PR; a v2 draft is then unreadable by the old schema and is discarded as unsupported, which the old loader already handles. Deploy GoGo-BE#581 before this client; an older backend would ignore the area.
