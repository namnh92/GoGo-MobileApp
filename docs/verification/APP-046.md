# APP-046 — invite request control

Refs #199. Host explicitly creates a code; render, room polling and foreground no longer create invitations. No automatic mutation retry. Plaintext code and retry intent are memory-only keys, excluded from persistence and cleared with session cache. Returning to the lobby reuses the unexpired code; revoking it clears that code. Retry-After gates manual retries and retries retain the same idempotency key.

Validation: typecheck and lint pass; unit suite 274 passed / 39 skipped; 11 lobby component tests and 5 invite tests passed. Invite tests simulate 300 seconds of polling for both 409 and 429 with one POST per user attempt, plus remount, foreground, revocation, room isolation and Retry-After. Jest reports an existing open-handle warning after the invite suite; not a clean process-exit claim.

Not run: five-minute physical-device DEV soak, actual join/preference latency, cold-start invite recovery. The server returns plaintext once; after a process restart the host must explicitly create a new code. No claim that device acceptance is complete. Rollback: revert this PR.
